## User Scenarios and Testing

### User Story 1 - 首屏探索图谱 (Priority: P1)

作为业务用户，我打开图谱型知识库时希望首先看到可交互的实体关系图，从而先理解全局结构，再按需查看原始记录。

**Independent Test**: 选择一个已有图谱投影的知识库，确认详情摘要后出现图谱画布；选择普通知识库，确认仍直接显示记录搜索和列表。

**Acceptance Scenarios**:

1. **Given** 一个具有图谱投影的知识库，**When** 用户从知识库目录选择它，**Then** 图谱 WebUI 必须位于详情摘要之后、记录内容之前，并默认显示当前筛选结果的节点和关系。
2. **Given** 一个没有图谱投影的知识库，**When** 用户打开它，**Then** 页面必须保留既有记录搜索、列表和分页顺序，且不显示图谱控件。

### User Story 2 - 聚焦实体与关系证据 (Priority: P1)

作为业务用户，我希望在画布中选择实体或关系，快速判断其邻接关系和支撑它的来源记录。

**Independent Test**: 在图谱画布点击实体和关系，确认信息面板分别显示一跳关系和证据；点击证据后出现既有逐条溯源对照。

**Acceptance Scenarios**:

1. **Given** 已加载的图谱画布，**When** 用户点击节点，**Then** 系统调用现有邻域接口、视觉突出该实体，并显示其一跳关系。
2. **Given** 已加载的图谱画布，**When** 用户点击关系，**Then** 系统调用现有证据接口、视觉突出该关系，并提供可打开的记录证据。
3. **Given** 信息面板中的一条证据，**When** 用户选择“查看前后对照”，**Then** 系统继续使用既有记录溯源体验，不复制或暴露额外源数据。

### User Story 3 - 筛选与可读性控制 (Priority: P2)

作为业务用户，我希望通过关键词、关系类型和画布控制收窄图谱，以便在密集医疗知识图中保持可读。

**Independent Test**: 使用关键词和关系筛选，确认画布、统计和空状态同步更新；使用缩放、重置和图例控件，确认它们不改变服务端数据。

**Acceptance Scenarios**:

1. **Given** 图谱知识库，**When** 用户提交关键词或关系类型，**Then** 系统调用既有图谱 API，画布只显示返回的节点和边，并保留筛选条件。
2. **Given** 图谱中没有符合筛选的数据，**When** 筛选完成，**Then** 用户看到明确的空状态和可用的清除筛选入口。
3. **Given** 已加载的图谱，**When** 用户使用缩放或重置视图，**Then** 仅改变当前浏览器视图，不写入服务端、不修改图谱投影。

## Scope and Impact

### In Scope

- 图谱型知识库在详情首屏优先展示原生可视化图谱画布和探索控件。
- 筛选结果的 SVG 节点/有向边、节点与边选择态、图例、缩放/重置及可访问的替代关系列表。
- 复用现有图谱、邻域、边证据和记录溯源 API；将记录浏览移至图谱区之后的“知识记录”区域。
- 空状态、请求错误反馈、键盘可聚焦控件和窄屏响应式布局。
- 新建图谱任务的实体（同义）消除配置、受约束的模型归并、别名投影及失败降级。
- 节点 `degree`/`aliases` 的向后兼容响应扩展，以及按连接度优先的 80 条关系画布。

### Out of Scope

- 不接入、运行、嵌入或复制 LightRAG 的 React/Sigma WebUI、服务端或存储。
- 不改写原始知识记录、来源证据、图谱编辑能力、历史图谱或证据/溯源权限。
- 不提供全量超大图渲染、持久化拖拽布局、图谱编辑、社区发现或跨知识库合并。

### Expected Project Impact

- **`frontend`**: 图谱型知识库的详情信息层级和图谱浏览呈现改变；非图谱知识库维持兼容。
- **`wiki`**: 前端工作区、API 使用说明与维护日志需要登记新的主视图行为和 LightRAG UI 参考边界。

### Cross-Project Behavior

单任务和批量任务创建请求增加可选 `entity_resolution_enabled`（默认 `false`）；图谱和邻域节点增加 `degree`、`aliases`。这些均为向后兼容的合同扩展；证据与溯源端点不变。

## Requirements

### Functional Requirements

- **FR-001**: 系统必须仅对具有图谱投影的知识库，把图谱 WebUI 排在详情摘要之后、知识记录区域之前；没有图谱投影的知识库必须保留记录优先顺序。— Sources: SRC-001, SRC-002
- **FR-002**: 系统必须使用现有图谱 API 返回的节点和边渲染有向可视化画布，清楚显示实体、关系方向和当前筛选结果。— Sources: SRC-001, SRC-003
- **FR-003**: 系统必须提供关键词和关系类型筛选、缩放/重置及图例/计数等探索控件；筛选不得超出后端现有返回上限，视图控制不得写入服务端。— Sources: SRC-001, SRC-003
- **FR-004**: 用户点击图谱节点时，系统必须复用邻域端点显示一跳关系；点击关系时，系统必须复用证据端点显示支撑记录，并能进入既有逐条溯源。— Sources: SRC-001, SRC-002, SRC-003
- **FR-005**: 系统必须在筛选无结果、图谱请求失败和窄屏环境提供可理解的状态或降级体验，并让每个主要图谱操作可通过可聚焦控件完成。— Sources: SRC-001, SRC-002
- **FR-006**: 当且仅当业务向导选择 `knowledge_triple` 时，系统必须显示默认勾选的“实体（同义）消除”选项；取消图谱类型后该选项必须隐藏。— Source: SRC-004
- **FR-007**: 单任务和批量 API 必须接受可选 `entity_resolution_enabled`，旧请求默认关闭；业务向导创建的图谱任务默认开启，混合批量任务不得影响非图谱任务。— Source: SRC-004
- **FR-008**: 开启消歧的新增图谱任务必须在图谱投影前仅将明确同义的已提取实体归并至输入中已有名称，保留原始三元组、记录与全部证据，并保存规范节点的别名映射。— Source: SRC-004
- **FR-009**: 消歧模型无效或失败时，任务必须按既有规范化规则继续发布图谱，并在任务验证信息记录“fallback”和原因。— Source: SRC-004
- **FR-010**: 图谱和邻域节点必须附带连接度和别名；画布必须只默认展示按连接度优先的 80 条当前关系，连接度高的节点更大且更靠近中心。— Source: SRC-004
- **FR-011**: 知识库详情在中大屏必须保持约 300px 左侧知识库列表和右侧全宽详情；中小屏切换为不溢出的单列。— Source: SRC-004
- **FR-012**: 图谱实体名称必须在圆形节点内居中显示；名称最多两行，长英文优先按词边界换行并以省略号截断，完整名称仍可经无障碍标签、提示和选中详情获得。节点半径与布局必须随之保持边和节点可读。— Source: SRC-005

### Key Entities

- **图谱投影**: `knowledge_triple` 知识库的只读 SQLite 派生图；一份图谱有多个规范化实体节点和去重关系边。
- **图谱视图**: 一个由当前筛选 API 响应驱动的临时前端画布；不改变或保存图谱投影。
- **边证据**: 将图谱边关联到一个或多个既有知识记录的只读证据集合，可继续回到记录溯源。
- **图谱节点别名**: 新增 `graph_node_aliases` 投影，记录规范图谱节点与其原始同义实体；不覆盖 `knowledge_records`。

## Edge Cases

- 图谱 API 返回空边时，画布显示空状态而不是陈旧节点；清除筛选后可重新请求完整的受限视图。
- 切换知识库、翻页或筛选时必须清除上一图谱的选中邻域和证据，避免跨知识库信息混淆。
- 同一对节点有多条关系时，必须仍可选择每条边的证据；标签重叠时可读性优先于完整文字展示，并保留替代列表。
- 未加载图谱或请求失败时不得阻断记录浏览和既有错误提示。
- 消歧模型返回输入外实体、冲突映射或无效格式时不得阻断任务；必须回退并保持原始节点投影行为。

## Success Criteria

- **SC-001**: 打开有图谱投影的知识库后，用户无需滚动经过记录列表即可看到图谱画布及实体/关系计数。
- **SC-002**: 用户能从任一可见节点取得一跳关系，并从任一可见边打开至少一条支撑记录的既有溯源对照。
- **SC-003**: 关键词或关系筛选后的可视节点/边与图谱 API 响应一致；无结果不会显示先前筛选的图数据。
- **SC-004**: 打开无图谱投影的知识库时，其记录查询、分页和溯源行为保持可用。
- **SC-005**: 开启消歧后，同义实体聚合为一个图谱节点，别名和两侧原始证据均可查询；关闭或降级时仍正常发布未语义合并的图谱。
- **SC-006**: 画布在默认结果中只显示 80 条关系，且高连接度节点的半径和中心距离分别不小于、且不大于低连接度节点的对应值。
- **SC-007**: 短中文、长中文与长英文实体均在圆内呈现；任一节点不超过两行，边端点不落入圆内。

## Assumptions

- 图谱 API 继续给当前筛选视图提供至多 200 条关系；画布二次挑选其中连接度优先的 80 条，不增加图形依赖。
- “参考 LightRAG”指采纳其首要画布和探索交互模式，不表示采用或部署其源码；此解释已记录在 [intake.md](./intake.md)。

## Dependencies

- 依赖当前图谱 API 和主前端构建环境；不依赖外部 LightRAG 服务或网络运行时。
